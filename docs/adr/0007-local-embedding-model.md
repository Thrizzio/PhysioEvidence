# ADR-007: Local embedding model, runtime, license, and compatibility
- Status: Accepted
- Date: 2026-10-15
- Context: Local operation should not require a paid remote API. Current pgvector schema uses 768 dimensions. Ollama provides lightweight local execution of Google's `embeddinggemma-2:270m`.
- Decision: Support `embeddinggemma-2:270m` via Ollama's HTTP `/api/embed` endpoint with 768-dimensional normalized vectors, asymmetric task formatting (query vs document), finite value validation, and structured error handling. Keep sentence-transformers and remote Gemini as configurable alternatives.
- Alternatives considered: Using Ollama chat endpoint (`/api/chat`, fails because embedding model does not support chat); `ollama embed` CLI command (fails because command does not exist in Ollama CLI); heavy sentence-transformers download; Gemini-only.
- Consequences and trade-offs: Requires a running local Ollama daemon (`ollama serve`); executes efficiently on 8GB VRAM with zero external API fees.
- Security, privacy, and licensing: Clinical literature and questions remain completely local on-device without network transmission.
- Performance/scaling implications: 270M parameter quantized model runs with sub-second batch latency on local GPU/CPU.
- Validation/evidence: Verified against local Ollama 0.40.4 instance with `embeddinggemma-2:270m`. Returns 768-dimensional finite unit-normalized vectors.
- Revisit when: Model updates or context length requirements change.
